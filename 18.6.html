18-6 · Mermaid 图表实战

智能客服系统：流程图与 ER 图

Mermaid 是"用文字画图"的图表库：只要写一段类 Markdown 的源码，就能渲染成流程图、ER 图、时序图等。为符合本站"资源全部本地化"要求，官方 CDN 的 mermaid.min.js（v10.9.1）已下载到 cdn/ 目录本地引用。本页用它绘制智能客服系统的对话处理流程图与数据库实体关系图（ER 图）。

一、智能客服对话流程图（flowchart）

用户提问后由机器人应答：命中知识库直接回复，未命中则澄清追问，两轮仍失败转人工并创建工单。

flowchart TD
    A([用户进入客服]) --> B[/输入问题/]
    B --> C{NLU 意图识别}
    C -->|识别成功| D{命中知识库?}
    C -->|识别失败| E[引导澄清提问]
    E --> B
    D -->|命中| F[返回知识库答案]
    F --> G{用户满意?}
    G -->|满意| H([评价并结束])
    G -->|不满意| I[机器人二次追问]
    I --> B
    D -->|未命中| J[致歉并推荐相似问题]
    J --> K{是否转人工?}
    K -->|否| B
    K -->|是| L[排队分配人工客服]

    subgraph M[人工服务子系统]
        L --> N[客服接入会话]
        N --> O[问题解决?]
        O -->|是| H
        O -->|否| P[创建工单]
        P --> Q[工单流转·专人跟进]
        Q --> R([回访闭环])
    end

    style A fill:#1d5d8f,color:#fff
    style H fill:#5cab69,color:#fff
    style L fill:#b3541e,color:#fff
    style R fill:#5cab69,color:#fff

语法要点：flowchart TD 声明自上而下布局；--> 连线，--|文字| 给线上加标签；{} 菱形判断、[/ /] 平行四边形输入输出、(()) 圆角端点；subgraph 分组泳道。

二、智能客服数据库 ER 图（erDiagram）

六个核心实体：用户发起会话，会话包含多条消息，消息命中意图并关联知识库条目；转人工后生成工单由客服处理。

erDiagram
    USER ||--o{ SESSION : "发起"
    SESSION ||--o{ MESSAGE : "包含"
    MESSAGE }o--|| INTENT : "命中"
    INTENT ||--o{ KB_ENTRY : "关联答案"
    SESSION ||--o| TICKET : "转人工生成"
    AGENT ||--o{ TICKET : "认领处理"

    USER {
        bigint user_id PK "用户ID"
        varchar nickname "昵称"
        varchar phone "手机号"
        datetime created_at "注册时间"
    }
    SESSION {
        bigint session_id PK "会话ID"
        bigint user_id FK "所属用户"
        varchar channel "渠道(web/app)"
        tinyint status "0机器人1人工2结束"
        datetime started_at "开始时间"
    }
    MESSAGE {
        bigint msg_id PK "消息ID"
        bigint session_id FK "所属会话"
        tinyint role "0用户1机器人2客服"
        text content "消息内容"
        bigint intent_id FK "命中的意图"
        float confidence "识别置信度"
    }
    INTENT {
        bigint intent_id PK "意图ID"
        varchar name "意图名称"
        varchar sample_utters "训练语料"
    }
    KB_ENTRY {
        bigint kb_id PK "知识条目ID"
        bigint intent_id FK "所属意图"
        varchar question "标准问题"
        text answer "标准答案"
        int hit_count "命中次数"
    }
    TICKET {
        bigint ticket_id PK "工单ID"
        bigint session_id FK "来源会话"
        bigint agent_id FK "处理客服"
        tinyint priority "优先级"
        tinyint status "0待处理1处理中2已闭环"
    }
    AGENT {
        bigint agent_id PK "客服ID"
        varchar agent_name "客服姓名"
        varchar group_name "技能组"
    }

语法要点：A ||--o{ B : 标签 表示一对多关系（左符基数：|| 恰好一个、o| 零或一个、}o 零或多）；实体块内列出属性，PK / FK 标注主外键。

本页用途描述客服对话从提问到工单的处理链路描述支撑该链路的 6 张数据表设计
<!-- 1. 引入库（本页已本地化：cdn/mermaid.min.js） --> <script src="cdn/mermaid.min.js"></script> // 2. 初始化：渲染页面中所有 <pre class="mermaid"> 源码 mermaid.initialize({ startOnLoad: true, theme: 'base', themeVariables: { fontSize: '14px' }, flowchart: { curve: 'basis' } }); // 3. 源码即图：缩进文本直接描述图形 <pre class="mermaid"> flowchart TD A([用户进入客服]) --> B[/输入问题/] B --> C{NLU 意图识别} </pre>

Mermaid 的优势：图即代码，可进 Git 版本管理、可程序化生成；缺点是超大规模图会难维护，此时应换专业绘图工具。
